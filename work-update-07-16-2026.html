Work Update · July 16, 2026

Single-Page Operations Viewer

Today’s work converted four separate Apps Script queue pages into one stable dashboard that runs inside the Meadows Housekeeping Google Sites page without disappearing during navigation.

4 Operational views unified
1 Persistent embedded viewer
2 Automated email events verified
End-to-end Workflow tested successfully

Overview

The Meadows Housekeeping operations interface previously used separate Apps Script HTML pages for Intake, Work Queue, Recommendations, and Completed Work. Each navigation link attempted to load a new /exec?view=... page inside the existing Google Sites embed.

The replacement uses one Dashboard.html document. Navigation now changes only the content inside the dashboard. The Apps Script frame remains loaded, and the browser never has to rebuild a nested web-app frame.

Problem Identified

The first queue change could load successfully, but later navigation caused the embedded viewer to disappear. Browser-console testing confirmed that the links, destinations, and target="_self" behavior were correct. The failure came from repeated Apps Script page navigation inside the Google Sites iframe, not from the queue data or action functions.

Design decision: preserve the existing Apps Script backend and replace page-to-page navigation with a single-page interface.

Work Completed

  • Replaced the multi-page doGet(e) HTML routing with a single response that serves Dashboard.html, while preserving the existing JSON response option.
  • Created one navigation bar with buttons for Intake, Work Queue, Recommendations, and Completed Work.
  • Added a shared #app-view container where each operational view is rendered without changing the web-app URL.
  • Connected each dashboard button to its existing server function: submissions, active work, recommendations, and completed work.
  • Integrated the full Intake cards, including acknowledgement and queue-sorting controls.
  • Integrated Work Queue controls for starting work, adding notes, and completing tasks.
  • Integrated Recommendations controls for review, notes, and archive actions.
  • Integrated Completed Work cards with timestamps, duration, notes, and email status.
  • Added loading states, active navigation states, error handling, and automatic view refresh after every successful action.

Current workflow

1 Submit Request
2 Acknowledge
3 Sort to Queue
4 Start Work
5 Add Notes
6 Complete & Report

Verification

A new request was taken through the complete production workflow: acknowledgement, queue sorting, work start, note entry, and completion.

  • The dashboard refreshed correctly after each state change.
  • The Google Sites embed remained visible through every view change.
  • The acknowledgement email was sent successfully.
  • The completion email was sent successfully.
  • The finished item moved into Completed Work with its updated record.
Result: the single-page dashboard is now a functioning end-to-end housekeeping request-management interface, not merely a display prototype.
