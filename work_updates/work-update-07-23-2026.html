Full product pages

Inventory 3.0 now provides a complete standalone page for each product. The product page is no longer limited to a compact popup inside the inventory browser.

  • Product image and category
  • Product name and manufacturer
  • Manufacturer product code
  • Container size and inventory unit
  • Inventory product ID
  • SDS revision, source, and verification information
  • Direct SDS and manufacturer-information buttons when available

Navigation and presentation

  • The original Details popup was retained for quick reference.
  • An Open full product page button was added.

Apps Script routing failure diagnosed and repaired

The stable deployment address was not changing. Internal navigation was accidentally rebuilding links from a temporary Google-hosted iframe address.

Inventory 3.0 could open correctly from Google Sites, but the Open full product page button could then lead to a blank or older-looking page. The failure appeared to be a deployment problem, but the actual cause was inside Scripts.html.

Incorrect routing source

window.location.origin + window.location.pathname

Inside an Apps Script application, this can resolve to a temporary address containing:

script.googleusercontent.com/userCodeAppPanel

Correct routing source

The application was already receiving the stable deployment address from Apps Script:

ScriptApp.getService().getUrl() → window.APP_URL → getAppBaseUrl() → all internal links

The getAppBaseUrl() helper was rewritten to use window.APP_URL. This repaired the full-product-page link and both Back-to-Inventory links without changing the outside deployment URL.

5

Stable deployment workflow established

The difference between an Apps Script deployment and a deployment version was clarified.

Existing deployment

  • Edit through Manage deployments.
  • Select New version.
  • Keep the same deployment ID and /exec URL.
  • Preserve bookmarks, Google Sites buttons, and QR codes.

New deployment

  • Creates another deployment ID.
  • Produces another /exec URL.
  • Can leave older versions active and accessible.
  • Should not be used for ordinary code updates.

Protected navigation rules

  • Do not build internal app links from window.location.
  • Do not use document.location for application routing.
  • Do not store temporary googleusercontent.com addresses.
  • Do not hard-code deployment URLs inside client-side scripts.
  • Use the server-provided window.APP_URL consistently.

Short post-deployment test

  • Open the Inventory 3.0 homepage.
  • Select a location.
  • Open a product’s Details panel.
  • Open the full product page.
  • Test Back to Inventory.
6

Longer-term application architecture

A central Klinswork URL registry was considered as a way to manage the addresses of Inventory 3.0, Tasker, Email Composer, and the Tool Center. Such a registry may still be useful for internal navigation and future replacement deployments.

The more important discovery, however, is that normal code updates should not require any link changes at all. Stable deployment URLs combined with a single canonical internal base URL remove most of the need for manual link maintenance.

One stable deployment address should serve as both the front door and the source for every internal route.
