Inventory 3.0

Inventory 3.0 was not merely updated today. It was conceived, designed, and created as a new system.

Inventory 3.0 was defined as a fresh start rather than another patch to the earlier inventory versions. The goal is a stable personal system for tracking cart inventory, recording quantity changes, documenting reasons, and preserving a reliable history.

Architecture established

  • Config.gs for configuration and shared constants.
  • DataService.gs for spreadsheet and data-access operations.
  • InventoryService.gs for inventory rules and business logic.
  • Validation.gs for checking inputs and preventing invalid operations.

This separated configuration, data access, inventory behavior, and validation instead of placing all responsibilities into one large script file.

Purpose of the system

  • Track current cart quantities.
  • Record inventory adjustments.
  • Document why an adjustment was necessary.
  • Preserve history for accountability and reporting.
  • Support dependable personal use even without broader department adoption.

Issues diagnosed and troubleshooting fixes

Phone layout appeared tiny

The Apps Script page was initially being rendered at desktop width and then shrunk to fit the phone. The cause was a missing viewport setting in doGet().

.addMetaTag('viewport', 'width=device-width, initial-scale=1')

After saving and redeploying, the page rendered at the correct mobile scale. Text became readable, cards became usable, and the interface stopped behaving like a miniature desktop page.

Images cropped after the mobile fix

Once the page scaled correctly, some images were cropped because fixed heights and object-fit: cover were forcing them to fill boxes by cutting away part of the image.

img { display: block; width: 100%; max-width: 100%; height: auto; object-fit: contain; }

The corrected approach preserves the complete image, maintains its proportions, and allows it to flex naturally with the page.

Favicon and home-screen icon troubleshooting

  • Resolved unsupported favicon-format issues.
  • Worked through incorrect generated image dimensions.
  • Improved contrast so the icon remains recognizable at small sizes.
  • Separated browser favicon behavior from mobile home-screen icon behavior.
  • Added a web-app manifest and linked it in the HTML.
  • Redeployed the Apps Script app after changes.
  • Recognized that browser and phone caching can delay visible updates.

This clarified the distinct jobs of the favicon, viewport metadata, manifest, and mobile home-screen icon.

Image preparation and transparency work

Product and interface images were reviewed and adjusted so they work more reliably inside Inventory 3.0 and the Tool Center.

Topics worked through

  • Exact pixel dimensions
  • PNG versus JPEG
  • White and transparent backgrounds
  • Alpha channels
  • Checkerboard transparency
  • Flattening and merged layers
  • Gray halos and edge artifacts
  • Scaling without cropping

Reliable transparency test

Place a bright-colored layer underneath the image in GIMP:

  • If the color shows through, the pixels are transparent.
  • If the checkerboard remains, it is baked into the image.

Prominence product-image repair

The Prominence floor-cleaner image had a gray background and a strange vertical artifact on the right. The product image was recreated with a clean edge, and a second version was produced with a solid white background for simple use in the inventory interface.

Future batch-processing workflow

The amount of manual image work demonstrated the value of a repeatable Python workflow using Pillow or a GIMP Python plug-in. A future script could:

  • Resize entire folders proportionally.
  • Prevent cropping.
  • Center products on consistent canvases.
  • Preserve transparency.
  • Create white-background copies.
  • Generate thumbnails and card-size images.
  • Create standard favicon and home-screen icon sizes.
  • Convert formats and standardize filenames.
