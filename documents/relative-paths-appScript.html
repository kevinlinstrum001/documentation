How Relative Paths Work in Apps Script

A Google Sheet can store a short path such as images/products/chem-007-air-freshener.png, but the sheet does not know where that file lives. The Apps Script code gives that path meaning by joining it to a public base URL.

The Core Idea

A relative path is an incomplete address. It describes where a file is located inside a known folder structure, but it does not include the website or repository address.

Base URL supplied by Code.gs https://raw.githubusercontent.com/kevinlinstrum001/inventory/main/
+
Relative value stored in the sheet images/products/chem-007-air-freshener.png
The Google Sheet is only storing text. The spreadsheet ID tells Apps Script which spreadsheet to open. It does not tell the browser where images or documents are stored.

The base URL in your code

JavaScript
const IMAGE_BASE_URL =
  'https://raw.githubusercontent.com/kevinlinstrum001/inventory/main/';

This line establishes the repository root. Every relative image path stored in the sheet is interpreted from this location.

How Images Are Referenced

In the Products sheet, an image can be stored as:

Sheet value
images/products/chem-007-air-freshener.png

Your original code sends that value through getImageUrl().

Code.gs
function getImageUrl(value) {
  const text = String(value || '').trim();

  if (!text) return '';

  if (/^https?:\/\//i.test(text)) {
    return text;
  }

  return IMAGE_BASE_URL + text.replace(/^\/+/, '');
}

The function performs three checks:

1
Is the value blank?

If so, return an empty string.

2
Is it already a complete URL?

If it starts with HTTP or HTTPS, return it unchanged.

3
Otherwise, treat it as relative.

Join it to the configured GitHub repository base URL.

Where the conversion occurs

Code.gs
product_image_url: getImageUrl(row[7]),

By the time the SDS view receives product_image_url, the value is already a complete URL.

SDS view
<img
  class="product-image"
  src="${escapeAttribute(record.product_image_url)}"
  alt="${escapeAttribute(record.product_name)}"
>

How Documents Should Be Referenced

The SDS sheet can use the same principle. Store only the path from the repository root:

Sheet value
docs/sds/Citrus-30-Day-Refill-SDS.pdf

The original code did not expand this path. It returned the cell value unchanged:

Original Code.gs
document_url: String(row[3] || ''),

That caused the browser to interpret the PDF path relative to the temporary Apps Script page address.

Why it failed: Apps Script does not automatically publish a docs/sds/ folder. A relative link placed directly in the HTML is resolved against the current script.googleusercontent.com page.

Recommended document base

Use GitHub Pages for PDFs when you want them to open in the browser:

JavaScript
const DOCUMENT_BASE_URL =
  'https://kevinlinstrum001.github.io/inventory/';

One reusable resolver

Code.gs
function resolveUrl_(value, baseUrl) {
  const path = String(value || '').trim();

  if (!path) {
    return '';
  }

  if (/^https?:\/\//i.test(path)) {
    return path;
  }

  return baseUrl + path.replace(/^\/+/, '');
}

Images

Code.gs
product_image_url:
  resolveUrl_(
    record.product_image_url,
    IMAGE_BASE_URL
  ),

SDS PDFs

Code.gs
document_url:
  resolveUrl_(
    record.document_url,
    DOCUMENT_BASE_URL
  ),

The HTML view can then use the complete PDF URL without any additional path logic:

SDS view
<a
  class="button"
  href="${escapeAttribute(record.document_url)}"
  target="_blank"
  rel="noopener noreferrer"
>
  Open SDS PDF
</a>

The Complete Data Flow

1
The Google Sheet stores a relative path.

docs/sds/Citrus-30-Day-Refill-SDS.pdf

2
Code.gs reads the cell.

The value is ordinary text at this stage.

3
The resolver joins it to a base URL.

The code decides whether the file belongs under the raw GitHub base or the GitHub Pages base.

4
The Apps Script view receives a complete URL.

The HTML does not need to know anything about the repository.

5
The browser loads the resource.

Images display in cards and SDS documents open in a new tab.

Key principle: The relative path is not related to the spreadsheet ID. It is relative to the base URL selected by your Apps Script code.

Troubleshooting

The image or PDF returns 404

Check the filename, capitalization, repository branch, folder structure, and whether the file was committed and pushed.

The PDF points to script.googleusercontent.com

The document URL reached the HTML as a relative path. Confirm that document_url passes through the resolver in Code.gs.

The PDF downloads instead of opening

Use the GitHub Pages base for documents rather than the raw GitHub base. Browser PDF settings can still force downloads, but GitHub Pages is the correct host for normal browser viewing.

A complete external URL is already in the sheet

The resolver returns complete HTTP or HTTPS URLs unchanged, so both relative paths and full URLs can coexist.
